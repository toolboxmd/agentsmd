**Requirements and who asked:** You want to know within hours if nightly-sync fails, without reading logs.
**Deleted:** A centralized log stack (Synology + Docker, Pieter Levels style) — nothing today needs log aggregation, only this one job needs a failure alert.
**Bottleneck:** nightly-sync can die before it reaches the email step, so the only signal you have never fires on failure.
**Checked myself:** You told me it crashed at startup for four nights straight, before the email step, and nothing else alerts on this job.

Recommendation: add one heartbeat check instead. Make nightly-sync touch a timestamp file as its very first line (before anything that can fail), then add a single small cron job that checks that timestamp exists and is fresh by 03:10, alerting you (NAS notification or a separate email) if not. No Docker, no log server, one mechanism that directly closes the "died before it could tell anyone" gap.
