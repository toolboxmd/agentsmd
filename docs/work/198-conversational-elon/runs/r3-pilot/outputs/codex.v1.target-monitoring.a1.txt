**Requirements and who asked:** You want to know when `nightly-sync` fails without reading logs.
**Deleted:** Central log storage and moving the job into Docker. Neither provides the missing alert by itself.
**Bottleneck:** The script sends its own email, so a startup crash also disables its notification.
**Checked myself:** Only what you told me: four missed runs, an expired token, and no independent alert.

You’re trying to catch missed syncs. I recommend one hosted heartbeat monitor: keep cron and Python on `edna`, and have the script ping the monitor only after a successful sync. Expect that ping daily after the 03:00 Europe/Warsaw run, with a deadline based on its normal runtime; if it never arrives, the monitor emails you independently.

That catches startup crashes and an offline Mac. Keep the existing summary email and fix the expired token if that is still unresolved. The Synology doesn’t need a new role for this.
