Centralized logging on the Synology is a reasonable "nice to have," but it wouldn't have solved your actual problem: a crash four nights running with silence. A log server only helps if you go look at it, and you already said you won't. What you need is a watchdog that alerts on *absence* of success, not a place to dump more text you'll never read.

Concretely: add a "dead man's switch" step — have `nightly-sync` ping a URL (self-hosted on the Synology via something like healthchecks.io's open-source image, or even a simple cron-checked file/Uptime Kuma push) the moment it *starts*, wrapped so it pings a "failed" endpoint on any exception, including the token error. If no ping arrives by 03:10, that service pushes you a notification (push/email/SMS) — that's the piece you're missing, not storage. Centralized logs in Docker on the Synology are a good follow-up for debugging *after* you're alerted, but build the alerting first since it's what would've caught last week's failure.
