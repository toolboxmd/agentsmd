**Deleted:** A new document system or custom approval tool. A naming convention as a control, because it enforces none of the contract terms.
**Bottleneck:** Authors can write to everything, so nothing approved can stay fixed.
**Checked myself:** Only what you told me. I have not seen the folder or the platform it runs on.

You want contract-compliant approvals live this week without changing how 15 people work.

I don't recommend shipping the APPROVED column with typed initials. It fails the contract on every point:

- Anyone can type anyone's initials.
- Authors can still edit the file after approval.
- The time is whatever someone types.
- Nothing stops an author from approving their own document.

My recommendation is to keep the folder and switch on what its platform already provides:

- **Released area:** Add a subfolder that only the three reviewers can write to.
- **Approval:** A reviewer approves by moving or copying the exact file into that subfolder. The platform then records who did it and when, under their own login.
- **Retention:** Set a seven-year retention policy on that subfolder.

Self-approval is then blocked by permissions, because authors cannot write there. One caveat: if a reviewer also authors documents, you need a rule or a separate check for that case.

Which platform hosts the folder (SharePoint, Google Drive, Dropbox, a file server)? That decides whether this is a one-hour setup or needs something more.
