You want double bookings to stop, and red formatting alone won't do that: it only flags a clash after both bookings are saved, and the owner requires the second one to be rejected at save time even when two agents submit at once. My recommendation is to keep the spreadsheet but route all new bookings through a small Apps Script booking form. The script takes a lock, checks the item for overlapping dates, and either saves the booking or rejects it with the clashing reservation shown. The booking range would then be protected so agents can't type into it directly. That is roughly a few days of work, so it may still fit this week. I'd add the red formatting too, but only as a backup to catch rows that already clash.

One decision for you: are you OK with agents no longer editing booking rows directly? Without that restriction, nothing can stop a conflicting save.
