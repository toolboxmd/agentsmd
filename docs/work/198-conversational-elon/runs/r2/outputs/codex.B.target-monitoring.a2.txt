You want to know when `nightly-sync` fails or never runs, without reading logs. I recommend adding a monitored heartbeat first: the script signals success only after completing, and an external service emails you if that signal hasn’t arrived by 03:00 plus its normal runtime and a buffer, catching startup crashes, missed cron runs, and `edna` being offline.

Central logs on the Synology could help investigate later, but they wouldn’t solve the unnoticed-failure problem by themselves; keep cron and Python as they are, skip Docker for this fix, and choose the alert deadline based on how long a healthy run takes.
