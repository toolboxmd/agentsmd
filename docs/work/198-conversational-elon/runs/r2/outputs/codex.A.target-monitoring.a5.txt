I’d start with a **missing-run alert for `nightly-sync`**. A central log helps investigate failures, but you’d still need something to notice when the job goes quiet.

Use a hosted dead-man’s-switch service such as Healthchecks.io:

- Expect a successful run every day after the 03:00 start, with a deadline based on its normal runtime.
- Have a small wrapper around the Python script send a start ping, then a success or failure ping based on its exit status. That catches startup failures like the expired token.
- If no success arrives by the deadline—even because `edna` is off, cron never runs, or the network fails—the service alerts you.
- Send alerts somewhere you’ll notice, such as a phone push notification, with email as backup. Keep the existing summary email.

The key is that **the alert must fire when the script sends nothing**. Adding another email step inside the script wouldn’t cover that.

The Synology can run Healthchecks in Docker if you prefer self-hosting, but it shares your home power and internet connection with `edna`. A hosted monitor can still notify you when the whole house goes offline, and it’s less infrastructure to maintain for one job.

Keep local, rotated logs for troubleshooting; central logging can come later if more machines need it. Before calling this done, test a startup failure and a missed run, and confirm both alerts reach you.
