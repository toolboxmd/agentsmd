## 2. Multi-turn before/after

[`multiturn.py`](multiturn.py): one session, five user turns (a code question;
research and recommend; edit and commit; `gh pr create`; have another agent
review). Each routed action is scored against reads made before it anywhere in
the session. Hosts load AgentsMD as `trigger_test.py` does; Claude Code runs one
`--input-format stream-json` process so SessionStart fires once, as in T3.
Canaries: [multiturn-canary.jsonl](multiturn-canary.jsonl) (12/12 passed: main
and branch load `# Global Agent Rules` and `operations`, Claude Code and
OpenCode also the session pointer, the control loads nothing).

A read counts only when the call names the file **and** the tool's own result
contains the file's first heading, so failed, refused or echoed reads do not
count. A run is valid only when all five turns completed (Claude Code: an
error-free result per turn; elsewhere exit 0 before the watchdog plus the host's
end-of-turn event). Both rules came from the independent review of #200; the
first run, scored without them, is withdrawn (below).

Arms: `main` `8cad98f`, `branch` `c0e91ab`, `none` no-guidance control. Models:
Claude Code `claude-opus-5-5` medium, Codex `gpt-6.1-sol` medium, Grok
`grok-4.7` medium, OpenCode `opencode/muse-spark-1.3-contributor-free`.
Records: [multiturn-r2.jsonl](multiturn-r2.jsonl), 5 valid runs per arm on
Claude Code, Codex and Grok.

Reworded rows: the file was read before the action, main / branch:

| Host | `delivery.md` at `gh pr create` | `version-control/index.md` at commit | `orchestration.md` at spawn |
| --- | --- | --- | --- |
| Claude Code | **0/5 / 5/5** | 5/5 / 5/5 | **3/5 / 5/5** |
| Codex | 5/5 / 5/5 | 5/5 / 5/5 | not measurable |
| Grok | 5/5 / 5/5 | 5/5 / 5/5 | **1/5 / 5/5** |
| OpenCode | not measurable | not measurable | not measurable |

Pass condition, frozen before the runs:

- **P1** (branch reads the file before the action in at least 4 of the runs where
  the action happened, with at least 3 such runs): passes for all three rows on
  Claude Code and Grok, and for delivery and version control on Codex. Codex
  orchestration is not measurable: `codex exec --json` emits the agents' `wait`
  calls but never the spawn itself (`orchestration.md` had been read by the
  end of that turn in 5/5 main and 3/5 branch runs).
- **P2** (no over-trigger): no reworded file was opened during the question or
  research turn in any run, on any arm or host.
- **P3** (no regression, at most 1 run below main): `research/index.md` and
  `implementation.md` 5/5 on both arms everywhere; `verification.md` 5/5 on
  both arms on Claude Code and Grok, and 5/5 (main) against 4/5 (branch) on
  Codex. That Codex miss read `verification.md` together with other files in
  one `cat` at call 8. Codex can truncate long command output, so the heading may
  not have been returned; the strict rule counts it as a skip.
- **P4** (discrimination): the control read no procedure and never loaded
  `operations` (5/5 runs on each of the three hosts).

**OpenCode.** The free route `muse-spark-1.3-contributor-free` has returned
`Rate limit exceeded` since about 19:00 UTC; a retry loop found it limited at
every probe through 20:26 UTC. OpenCode is not measured in this round; the
result will be reported on #164 once the route answers.

**Runs not counted.**
- First run (records [multiturn.jsonl](multiturn.jsonl), arms `8cad98f` and
  `2b04650`), withdrawn after review. It counted Codex commands that failed
  (`cat undefined/...`) as reads, and counted stalled OpenCode sessions as
  valid. Its row text for version control also lacked the pre-edit trigger.
- One Claude Code batch crashed on a stream event whose `message` is a string
  (2 control runs written: [multiturn-r2-claude-crashed-batch.jsonl](multiturn-r2-claude-crashed-batch.jsonl)).
  The parser fix (`ce6c8ac`) changes no scoring rule, and the batch was rerun in full.
- In that rerun, the checkout guard aborted the fifth `main` run when another
  application rewrote `~/.codex/config.toml` (the runs use temporary Codex
  homes). One replacement run each for `main` and `branch` filled the cells.

**What this does not show.** The short session does not reproduce the real
skips of version control on Claude Code: main already reads it 5/5. The real
misses come from long sessions (dozens of turns, many tasks, compaction) that a
five-turn run does not reach. The re-measurement on real sessions after release
(#164 acceptance) is the check for those rows.
