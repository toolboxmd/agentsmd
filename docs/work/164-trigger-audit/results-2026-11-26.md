# Real-session trigger follow-up (Issue #164, 2026-11-26)

[PR #240](https://github.com/toolboxmd/agentsmd/pull/240) reworded Delivery,
Orchestration and Version control. [PR #242](https://github.com/toolboxmd/agentsmd/pull/242)
brought the changes to main in v17.3.0 on 19 October 2026. This follow-up
uses the first 14 complete UTC dates beginning at least a week after that
release, 27 October through 9 November inclusive. The seven complete dates
immediately after release, 20 through 26 October, provide a sensitivity check.

## Method

Run the retained [measure.py](measure.py) row predicates against existing
Agent Observer 1.9.0 records on bestia. Use the ledger in SQLite `mode=ro`.
Use one unit per session (per rollout source for Codex), with the baseline's
temporary working-directory exclusions. The main column includes children.
The sample predates this audit.
Cutoffs select session starts, as in the baseline. Later events in those
sessions may count. No model runs, synthetic scenarios, new imports, or reads
from the Chromeria state database were needed.

As in the baseline, a row fires when its required file has a matching read or
Skill call by the first observable triggering step. This counts matching
calls, without testing read success, context resets, or whether the agent
followed the procedure. A row can fire on one task in a session and still be
missed on a later task. The commit and PR proxies cover subsets of Version
control and Delivery. Shell patterns can match quoted commands and help calls.

For reproduction, use the scorer at `494be77ec7e9ee9ed459ef632c1485a516b2b181`.
In its ledger loader, omit the submissions UNION and bind the session key
once. The old query fails on Observer 1.9.0 with `no such column: rowid`
and prompt excerpts cannot reproduce the native prompt rules. Bound the SQL
session start to `started_at >= since AND started_at < until`, apply the
same bounds to split rollout starts, and use the `idx_events_session` index
for the per-session event query. Extend `_aliases` by duplicating every
`workflows/` tail with the prefix `procedures/` (keep the old alias). Use
the original `measure()` and row predicates for the main table and repeat
with children removed for the top-level check. The procedure alias restores
the renamed paths without changing trigger conditions.

All rows have the same counts with the one child excluded. The earlier-week
sample had 819 Claude Code, 574 Codex and 76 Grok units, all top-level by
the ledger's classification. The ledger had no units for the October 1
baseline window, so the comparison uses the published baseline. Ledger
child classification and rollout coverage can differ from native records.
OpenCode had no follow-up records. Muse was outside the baseline scope.
Agent Observer recorded an AgentsMD version for 57 of 750 session records
before exclusions in the main window. The cohort is post-release by date,
with individual installation and procedure exposure largely unknown. The
September native baseline was validated against an older Observer ledger
for tool-triggered rows. The event predicates remain comparable on
observable calls, but the cohort, source coverage and tooling mix prevent a
like-for-like effect estimate.

### Reworded rows

- **Delivery** fell from 92% skips (11/12) to 26% (13/50).
- **Version control** fell from 60% skips (9/15) to 24% (25/103).
- **Orchestration** had no trigger in the main window under the old matcher,
  which predates the T3 delegation tool. An expanded check found 12% skips
  (14/116), including 64% in Claude Code (14/22) and 0% in Codex (0/94).
  The historical 80% used a different trigger.

For the expanded check, add a spawn action on the original step for a
non-command tool whose name ends in `__delegate_task`, or
an `exec` command containing a literal `tools.mcp__t3_code__delegate_task`
followed by optional whitespace and an opening parenthesis. Count at most
one added spawn per Codex tool event because the scorer can emit both a
command action and a whole-program fallback for that event.
Similarly, add a PR-create proxy for a tool whose name ends in
`__pull_request_create` or its literal code-mode call. The PR-create extension
did not change the Delivery or Verification totals. After deduplication the
expanded check found no bounded-delegation opportunities in the main window.
A single Codex tool event does not establish whether it launched agents in
parallel.

The earlier week had 13% Delivery skips (18/136), 20% Version control skips
(33/165) and 16% expanded Orchestration skips (21/132). Delivery and Version
control remained below their October 1 skip rates in both windows. Claude
Code still skipped 11/23 Delivery and 14/25 Version control opportunities in
the main window. The earlier week showed 9% Finalization skips (10/117)
versus 55% (21/38) in the main window.

### Remaining work and unmeasured rows

Using October 1's cutoff of eight triggers, the worst legacy-proxy results
are Ticket decomposition (27/27 skips), Delivery profile (11/11), and
Finalization (21/38). Check whether the first two proxies identify genuine
procedure opportunities before changing their wording. Check Claude Code
Finalization (17/21 skips), then the remaining Claude Code misses on
Orchestration, Version control and Delivery. Verification, Implementation,
and the Operations entry point also show lower pooled skips than October 1
at eight or more triggers in both samples. Technical writing and Test design
show lower skips than the 14-day September comparison.

The baseline has no tool-call trigger for Context, Research, Software design,
Prototype, Diagnosis or Reconciliation. Preferences pruning has no row in
the retained instrument. The prompt-dependent Grilling, Wayfinder,
Specify/tickets, Review and Reflection rates need full prompt coverage.
An edit-only Reflection proxy would measure a different row. The dash cells
for other current rows mean the legacy proxy detected no opportunities.
The audit leaves #164 open because several rows still miss observable
opportunities and the missing coverage prevents a complete comparison.
